7. SEGURANCA, ACESSO E CONFORMIDADE
============================================================

CONTROLES CONFIRMADOS (em producao):

Autenticacao:
- Hash de senha: bcryptjs com 10 rounds de salt
- Requisitos de senha: 8+ chars, 1 maiuscula, 1 minuscula, 1 digito, 1 especial
- Verificacao de email obrigatoria para ativacao de conta
- Rate limiting por IP e email (persistido no banco):
  - LOGIN: 5 tentativas / 15 min
  - REGISTER: 3 / hora
  - FORGOT_PASSWORD: 2 / hora
  - RESET_PASSWORD: 3 / hora
  - VERIFY_EMAIL: 5 / 15 min
  - RESEND_ACTIVATION: 3 / hora
  - ACCEPT_INVITE: 10 / 15 min
  - REQUEST_TRANSFER: 10 / 15 min
  - RESPOND_TRANSFER: 10 / 15 min

Sessao:
- JWT com expiracao de 7 dias
- Cookie: httpOnly, secure (producao), sameSite: strict
- Whitelist de sessao no banco (tabela Session) — verificada em cada request
- Sessao unica por usuario (login revoga anteriores)
- Reset de senha revoga todas as sessoes
- Middleware (proxy.ts): verifica JWT, limpa cookie invalido, redireciona

Autorizacao:
- RBAC por workspace: OWNER > ADMIN > MEMBER > VIEWER
- Verificacao de role em todas as server actions (via getLoggedUser + assertColumnPermission/checkCardPermission)
- Allowlist de roles em convites/updates (prevencao de injecao de papel)
- Filtro de permissao por contexto: MEMBER so edita cards que criou ou e responsavel
- OWNER-only: encerramento de board, exclusao de atividades, gestao de membros

Validacao de inputs:
- Sanitizacao XSS (remocao de HTML tags) em todos os campos de texto
- Limites de tamanho: nome 100 chars, titulo 200 chars, descricao 5000 chars
- Validacao de email (regex + normalize + max 254 chars)
- Validacao de IDs sequenciais (numerico-only)
- Validacao de token de convite (formato UUID)
- Verificacao de email do destinatario no aceite de convite

Security headers (via next.config.ts):
- Content-Security-Policy (CSP) completo
- Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
- X-Content-Type-Options: nosniff
- X-Frame-Options: DENY
- X-XSS-Protection: 1; mode=block
- Referrer-Policy: strict-origin-when-cross-origin
- Permissions-Policy: camera=(), microphone=(), geolocation=()

Integridade de dados:
- Transacoes atomicas (prisma.$transaction) para operacoes compostas
- Protecao de dtcon contra reabertura indevida
- NOT NULL enforcements em campos de auditoria
- Validacao de existencia de entidades em transferencias

Protecao de segredos:
- .env no .gitignore
- MOCK_USER_ENABLED removido (bypass de dev eliminado)
- Tokens de convite nao expostos em respostas de API
- Mensagens de erro genericas para o cliente (allowlist de mensagens conhecidas)

CONTROLES NAO CONFIRMADOS:
- Criptografia de dados em repouso (disco/banco)
- TLS termination (reverse proxy nao documentado)
- Backup automatizado do banco de dados
- Rotacao de JWT_SECRET
- Monitoramento de intrusao (IDS/IPS)
- WAF (Web Application Firewall)
- Segregacao de rede entre containers
- Scan de vulnerabilidades em imagens Docker
- Politica de retencao de logs
- Plano de resposta a incidentes

RISCOS IDENTIFICADOS:

1. JWT sem refresh token (S-009): sessao expira abruptamente apos 7 dias sem aviso.
   Impacto: UX ruim + possivel perda de dados em formulario.
   Recomendacao: Implementar sliding session ou refresh token.

2. Papel VIEWER nao auditado (S-010): VIEWER pode ter acesso indevido a acoes de escrita.
   Impacto: Possivel escalacao de privilegio.
   Recomendacao: Auditar e implementar verificacao de VIEWER em todas as actions.

3. CSP com 'unsafe-inline' e 'unsafe-eval': reduz eficacia contra XSS.
   Impacto: XSS persistente pode executar scripts mesmo com CSP.
   Recomendacao: Migrar para nonce-based CSP.

4. Sem backup documentado: perda total de dados em caso de falha do container/disco.
   Impacto: Critico — perda irreversivel de dados.
   Recomendacao: Implementar backup automatizado com verificacao de restauracao.

5. Sem monitoramento continuo: falhas e ataques podem passar despercebidos.
   Impacto: Tempo de deteccao indefinido.
   Recomendacao: Implementar logging estruturado + alertas.

6. Enumeracao de email (S-034): possivel descobrir emails cadastrados.
   Impacto: Facilitacao de ataques direcionados.
   Recomendacao: Mensagem generica para registro e recuperacao.

RECOMENDACOES TECNICAS DE SEGURANCA:
- Implementar refresh token com sliding session
- Auditar role VIEWER em todas as server actions
- Migrar CSP para nonce-based (eliminar unsafe-inline/eval)
- Documentar e implementar backup automatizado
- Implementar logging estruturado (JSON) para acoes de seguranca
- Adicionar 2FA/TOTP (item S-040 planejado)
- Implementar soft-delete com periodo de retencao (item S-043)
- Implementar export de dados do usuario (LGPD art. 18, item S-044)
