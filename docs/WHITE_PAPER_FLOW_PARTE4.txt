9. OPERACAO, SUSTENTACAO E MANUTENCAO
============================================================

COMO O SISTEMA E OPERADO NO DIA A DIA:
- Aplicacao servida via Docker Swarm em container Node.js 22 Alpine
- Banco de dados PostgreSQL em container separado (pgvector) no mesmo host
- Sem evidencia de dashboard de monitoramento ou alertas automaticos
- Metricas disponibilizadas sob demanda via /admin/diagnostics
- Logs disponibilizados via stdout do container (console.error)

COMO SAO FEITAS ATUALIZACOES E DEPLOYS:
- Processo documentado:
  1. git pull (atualiza codigo no servidor)
  2. docker build (imagem Node 22 Alpine com build Next.js webpack)
  3. docker push 127.0.0.1:5000/flow:<commit-sha> (envia para registry local)
  4. docker service update (atualiza servico no Swarm)
  5. Rollback automatico se container nao iniciar com sucesso
- Build utiliza obrigatoriamente --webpack (Turbopack incompativel com musl/Alpine)
- Migrations NAO sao executadas automaticamente - SQL puro gerado e executado manualmente
- Prisma generate executado no build (dentro do Dockerfile)

DEPENDENCIAS DE INFRAESTRUTURA:
- Servidor Linux "hv5srvd" com Docker Swarm
- PostgreSQL (container pgvector)
- Registry Docker local (127.0.0.1:5000)
- Variaveis de ambiente: DATABASE_URL, JWT_SECRET, RESEND_API_KEY, RESEND_FROM_EMAIL, NEXT_PUBLIC_APP_URL
- Node.js 22 runtime

PONTOS UNICOS DE FALHA:
1. Servidor unico (hv5srvd): sem redundancia ou failover
2. Banco PostgreSQL em container unico: sem replica ou cluster
3. Registry local: se indisponivel, deploy falha
4. Resend API: se indisponivel, ativacao de conta e convites param
5. CDN cloudflare (html2pdf.js): se indisponivel, PDF nao gera

ESTRATEGIA DE BACKUP:
- Informacao nao identificada nos materiais fornecidos.

COMO INVESTIGAR ERROS:
- Logs: stdout/stderr do container Docker (console.error)
- Diagnostico: /admin/diagnostics com metricas agregadas
- Historico: ActivityLog e card_act para auditoria de dominio
- Nao ha: APM, tracing distribuido, centralizacao de logs, alertas

CONHECIMENTOS NECESSARIOS PARA MANTER O FLOW:
- TypeScript 5, Next.js 16, React 19, Prisma 7, PostgreSQL
- Docker/Docker Swarm, CSS Modules, JWT, Git

REQUISITOS PARA NOVA EQUIPE:
1. Acesso ao repositorio Git
2. Acesso ao servidor hv5srvd (SSH)
3. Acesso ao banco PostgreSQL
4. Variaveis de ambiente completas
5. Conta Resend configurada
6. Conhecimento do ROADMAP.md
7. Compreensao do deploy manual
8. Schema Prisma e migracoes manuais
9. Regra "dtcon como unico criterio de conclusao"
10. CLAUDE.md / AGENTS.md para padroes

11. DIFERENCIAIS TECNICOS E ESTRATEGICOS
============================================================

1. CENTRALIZACAO DA GESTAO:
   Evidencia: Multi-tenant com workspaces tipados, boards, cards. Dashboard unificado.

2. CONTROLE DE ACESSO GRANULAR (RBAC):
   Evidencia: 4 papeis, verificacao em todas as actions, hook useWorkspacePermissions.

3. AUTOMACAO DE RELATORIOS COM PARECER TECNICO:
   Evidencia: Semaforo automatico, KPIs, projecao de velocidade, export PDF.

4. RASTREABILIDADE COMPLETA:
   Evidencia: card_act, ActivityLog, campos obrigatorios created_by/moduser/dtmod.

5. INTEGRIDADE DE DADOS POR DESIGN:
   Evidencia: Transacoes atomicas, NOT NULL, protecao dtcon, consistencia coluna<->dtcon.

6. FLUXOS DE APROVACAO FORMAIS:
   Evidencia: Solicitacao/aprovacao de encerramento, transferencia com aceite.

7. SEGURANCA EM PROFUNDIDADE:
   Evidencia: Rate limiting, XSS sanitization, security headers, sessao revogavel.

8. ARQUITETURA MODERNA:
   Evidencia: Next.js 16, React 19, TypeScript strict, Prisma 7, Actions/Services/Repositories.

9. OPERACAO CONTAINERIZADA:
   Evidencia: Docker multi-stage, Swarm com rollback automatico.

10. EVOLUCAO PLANEJADA:
    Evidencia: Roadmap com 60+ itens categorizados por area e prioridade.
